# أنشئ هوية المتجر

حوّل موجز التاجر إلى ثلاث صور مستقلة ثم قسم ألوان بسطرَي HEX فقط. لا تعرض أي تقرير أو ملف مساعد.

أنشئ ثلاث صور منفصلة، كل صورة في ملف مستقل ومرفق تنزيل مستقل. ممنوع جمع الصور الثلاث في صورة واحدة.

1. `brand-catalog.png` 1536x1024.
2. `logo-ar.png` 1024x256.
3. `store-icon.png` 32x32.

## ابدأ هنا

1. اقرأ `references/input-contract.md` و`references/production-method.md`.
2. استخدم `assets/copy-paste-prompt.md` عند طلب نسخة جاهزة للصق.
3. استخدم `assets/output-template.md` لشكل الرد النهائي فقط، و`references/brand-kit-schema.md` لعقد ملفات التسليم، لا لإنشاء ملف JSON.

## سير العمل

1. اطلب فقط الاسم العربي كما يجب أن يظهر، وما الذي يبيعه المتجر. إذا غاب المطلوب، اسأل سؤالًا قصيرًا واحدًا. احترم أي تفضيل يذكره التاجر من تلقاء نفسه، من دون طلبه كحقل ثالث.
2. فكّر داخليًا في ثلاثة اتجاهات مختلفة فعلًا، ثم اختر الأقوى. لا تعرض الاتجاهات أو سبب الاختيار للتاجر.
3. ابنِ فكرة مركزية قابلة للملكية مرتبطة بالاسم أو المنتجات: كلمة عربية مقروءة بطابع مخصص، ورمز مميز متكامل معها، وتكوين أو مساحة سلبية مقصودة. تجنب النص المخزني مع دائرة أو قطرة أو حقيبة أو سلة أو زجاجة أو عين أو شفاه أو حبة، وتجنب القصاصات والزخرفة العشوائية.
4. اختر لونين فقط: `Primary` و`Secondary` بصيغة HEX مختلفة. يجوز استعمال درجات أو تدرج مشتق منهما ولمعات حيادية داخل الأصل، لكن لا تعلن ألوانًا رسمية إضافية.
5. استخدم الرمز والهندسة نفسيهما تمامًا في الشعار والأيقونة؛ الأيقونة ليست تصميمًا جديدًا. راجع داخليًا وضوحها عند 32x32.
6. حدّد القدرة قبل التسليم:
   - نفّذ ثلاث عمليات إنشاء/تصدير صور مستقلة، لا عملية واحدة: أنشئ logo-ar أولًا، ثم اشتق store-icon من علامة الشعار الفعلية، ثم كوّن brand-catalog من الاثنين. تحقق من الثلاثة قبل الإرفاق.
   - عند توفر PNG: سلّم `brand-catalog.png` 1536x1024 RGB أو RGBA 8-bit غير متداخل (الشفافية اختيارية)، و`logo-ar.png` 1024x256 RGBA 8-bit غير متداخل؛ الأركان الأربعة شفافة و1% على الأقل `alpha=0` <=1,950,000، و`store-icon.png` 32x32 بالشروط نفسها <=1,950,000، ثم Primary وSecondary.
   - SVG استثناء فقط إذا كانت البيئة Claude فعلًا وتعذر PNG لأن توليد الصور أو حفظ/إرفاق الملفات غير متاح: سلّم ثلاثية `brand-catalog.svg` 1536x1024 و`logo-ar.svg` 1024x256 و`store-icon.svg` 32x32، ولا تخلط الصيغ. إن تعذر الإرفاق، أعطِ ثلاث كتل SVG مسماة ثم Primary وSecondary.
   - في ChatGPT وGemini وManus وكل بيئة ليست Claude، لا تسلّم SVG أبدًا ولا تستبدل PNG ببرومبتات أو تنسيق آخر.
   - إذا لم تكتمل ثلاثية PNG أو ثلاثية SVG المسموح بها في Claude، فلا تخرج أي ملف أو لون جزئي. أخرج وحدها: `تعذر إنشاء وإرفاق ملفات PNG الثلاثة الفعلية في هذه البيئة.`
7. في وضع SVG، يجب أن تكون الأصول الثلاثة قائمة بذاتها وبالهندسة نفسها للشعار والأيقونة. لا تسمح بـ`script` أو معالجات أحداث `on*` أو `foreignObject` أو HTML أو `image` أو `href` أو `xlink:href` أو `style` أو خطوط أو روابط أو موارد خارجية أو data URI أو Raster مضمن.
8. افحص بصمت قبل التسليم بالأمر:

```bash
node scripts/validate-brand-kit.mjs <primary-hex> <secondary-hex> <catalog-asset> <logo-asset> <icon-asset>
```

واستخدم `--claude-fallback` مع ثلاثية SVG لاستثناء Claude أعلاه فقط.

## عقد التسليم

أعد للتاجر هذا فقط، بالترتيب:

1. مرفق تنزيل فعلي: `brand-catalog.png` 1536x1024.
2. مرفق تنزيل فعلي: `logo-ar.png` 1024x256.
3. مرفق تنزيل فعلي: `store-icon.png` 32x32.
4. `Primary: #RRGGBB`.
5. `Secondary: #RRGGBB`.

الكتالوج لوحة عرض مستقلة ومسموح أن تجمع الألوان ومعاينات الهوية، لكنه لا يحقق الشعار أو الأيقونة؛ تسليم لوحة واحدة فقط أو قصّها لإيهام وجود ثلاثة ملفات يفشل. أسماء الملفات أو النص وحدها ليست مرفقات ولا تسليمًا. لا تسلّم JSON أو تقريرًا أو mockup أو أي نص إضافي.

## حدود إلزامية

- لا تنسخ منافسًا أو مصممًا حيًا، ولا تستخدم أصلًا بلا ترخيص.
- لا تقل إن PNG أُنشئ عندما تكون النتيجة SVG.
- لا تضع اسمًا إنجليزيًا أو شعارًا فرعيًا أو علامة مائية أو خلفية شطرنجية مزيفة أو نصًا إضافيًا داخل الأصول.
- تجنب الواقعية الفوتوغرافية، ثلاثي الأبعاد، الكليشيهات القطاعية، والفوضى البصرية.
- لا تكشف محاولات المفاهيم أو الفحص الداخلي أو سبب رفض البدائل.

## تعريف النجاح

يحصل التاجر على ثلاث صور مستقلة قابلة للتنزيل ثم لونين قابلين للنسخ؛ الشعار والأيقونة من العلامة نفسها والكتالوج مبني منهما. SVG ليس نتيجة عامة، بل استثناء Claude للثلاثية فقط.
