# أنشئ هوية المتجر

حوّل موجز التاجر إلى ثلاث صور PNG منفصلة ونتيجة نصية واحدة. لا تعد استخدام لوحة مثال أو تشغيل سابق؛ كل قرار لون أو شكل يبدأ من معلومات المتجر الحالي.

> **قاعدة غير قابلة للتجاوز:** أنشئ وحرّر الصور النقطية Raster مباشرة، واحفظ PNG مباشرة. يُمنع منعًا تامًا استخدام SVG أو HTML/CSS أو HTML Canvas أو Inkscape أو أي ملف أو رسم أو أداة متجهية، حتى كمسودة أو ملف مؤقت أو مرحلة وسيطة أو خطوة تحويل إلى PNG. لا يكفي أن يكون الناتج النهائي PNG. إذا كانت الأدوات المتاحة لا تستطيع تنفيذ ذلك، استخدم `prompts_only` ولا تغيّر طريقة الإنتاج.

## ابدأ هنا

1. اقرأ `references/input-contract.md` لتحديد المدخلات وما يمكن استنتاجه.
2. اقرأ `references/production-method.md` قبل اختيار الألوان أو إنتاج الصور، واستخدم `references/brand-kit-schema.md` عند كتابة manifest.
3. استخدم `references/source-register.md` للمعايير المتغيرة، وتحقق من الصفحة الرسمية عندما يمكن أن يتغير الدعم أو المقاس.
4. إذا كان المستخدم يريد نسخة يلصقها مباشرة في GPT أو Gemini، استخدم `assets/copy-paste-prompt.md` مع بياناته.

## سير العمل

1. ابدأ بمدخلين فقط: اسم المتجر بالعربية، وما الذي يبيعه. اقبل تفضيلًا اختياريًا واحدًا للون أو الطابع، ولا تطلب من التاجر تحديد الجمهور أو 3–5 سمات أو قائمة أصول.
2. إذا غاب أحد المدخلين المطلوبين، اسأل عنه بسؤال واحد قصير. عدا ذلك ابدأ مباشرة، وسجّل ما تختاره من جمهور أو طابع أو لون بوصفه قرارًا تصميميًا مقترحًا لا حقيقة عن العميل.
3. اشتق ثلاثة اتجاهات مختلفة من الموجز، ثم قيّمها بحسب الملاءمة، وضوح الاسم العربي، التميز عن الكليشيهات، وعمل الرمز عند 32×32. اختر واحدًا ووضح السبب.
4. اختر للاتجاه الفائز لونًا رئيسيًا وثانويًا مخصصين، مع `on_primary`، `on_secondary`، `background`، و`on_background`. لا تبدأ من لوحة مثال ولا تفترض أن لونًا معينًا يعني «الثقة» أو «الفخامة» بلا دليل.
5. احسب التباين، وارفض أي لوحة لا تحقق 4.5:1 للنص العادي و‎3:1 للعناصر البصرية اللازمة. الشعار نفسه مستثنى من حد نص WCAG، لكن ألوان الواجهة ليست مستثناة.
6. سلّم أربعة مخرجات منفصلة، لا صورة واحدة تجمعها:
   1. `brand-board.png`: لوحة عرض كاملة للهوية، PNG بمقاس 1536×1024.
   2. **ألوان الهوية نصًا**: قيم HEX والأدوار ونسب التباين في الرد، وليست صورة.
   3. `logo-ar.png`: شعار عربي مستقل، PNG شفاف فعليًا بمقاس 1024×256.
   4. `store-icon.png`: أيقونة مستقلة، PNG شفافة فعليًا بمقاس 32×32، ومعها تقرير فحص نصي.
7. اكتب مرساة بصرية مشتركة تصف هندسة الرمز، سمك الخط، الألوان ومواضعها، وما يمنع تغييره. انسخ المرساة حرفيًا في برومبتات الشعار والأيقونة ولوحة الهوية، وسجلها في `brand-kit.json`. واكتب داخل كل برومبت مستقل: `مسار الإنتاج: direct_raster_png فقط؛ يمنع SVG وHTML وInkscape وأي وسيط متجهي في جميع المراحل.`
8. أنتج كل صورة مباشرة بأداة توليد أو تحرير صور Raster واحفظها كملف PNG مستقل. يجب أن يظهر اسم المتجر العربي نفسه داخل صورة الشعار، لا كنص منفصل عنها. لا ترسل طلب صورة واحدًا للحزمة كلها، ولا تقص الشعار أو الأيقونة من لوحة الهوية. أنتج الشعار والأيقونة أولًا، ثم أرفق ملفيهما كمرجعين عند بناء لوحة الهوية متى دعمت الأداة الصور المرجعية.
9. إذا لم يدعم مولد الصور المقاس النهائي بشكل أصلي، ولّد بنسبة الأبعاد الصحيحة ثم اسمح فقط بقص ملف PNG أو حشوه أو إعادة تحجيمه أو ضغطه بأداة Raster. لا تستخدم هذه الخطوة لرسم الشعار أو كتابة الاسم، ولا تحوّل من SVG أو HTML أو أي تنسيق متجهي. لا تعتبر الملف جاهزًا حتى يصل إلى المقاس المطلوب بالضبط دون تشويه.
10. افتح الصور الثلاث وراجع الاسم العربي حرفًا حرفًا، وظهور الأيقونة عند 32×32 فعليًا، واستقلال الملفات، وتطابق هندسة الرمز والألوان بينها. إذا أخطأ مولد الصور في العربية، أعد توليد الصورة أو حرّرها داخل الصورة Raster مباشرة بحد أقصى ثلاث محاولات. إذا بقي الاسم خاطئًا، ارفض النتيجة وانتقل إلى `prompts_only`؛ لا تستخدم SVG أو HTML أو Inkscape لتصحيحه.
11. أنشئ `brand-kit.json` وملخصًا باستخدام `assets/output-template.md`، ثم شغّل:

```bash
node scripts/validate-brand-kit.mjs brand-kit.json
```

## وضعا التسليم

### `assets_ready`

استخدمه فقط عند وجود ملفات PNG الثلاثة فعليًا، وإنتاجها عبر مسار `direct_raster_png`، ونجاح فحص المقاس والنوع، والشفافية للشعار والأيقونة، واستقلال الملفات. أي استخدام لـ SVG أو HTML أو Inkscape أو وسيط متجهي يجعل النتيجة مرفوضة حتى لو كانت الملفات النهائية PNG. الحد المحافظ لملفي رفع الشعار والأيقونة هو 1,950,000 بايت لكل ملف حسب عقد الواجهة المزود للمهمة؛ لوحة الهوية ملف عرض وليست ملف رفع لهذين الحقلين.

### `prompts_only`

استخدمه عندما لا تملك أداة إنتاج أو حفظ صور. سلّم الألوان نصًا وثلاثة برومبتات مستقلة للشعار والأيقونة ولوحة الهوية، واكتب بوضوح: «لم تُنشأ صور جاهزة للرفع». لا تسمّ المخرج شعارًا نهائيًا.

## حدود إلزامية

- لا تنسخ شعارًا أو رمزًا أو لوحة من منافس، ولا تطلب من المولّد تقليد مصمم حي بالاسم.
- لا تستخدم SVG أو HTML/CSS أو HTML Canvas أو Inkscape أو Illustrator أو Figma أو أي رسم/تتبّع/ملف متجهي في أي مرحلة. لا تنشئ وسيطًا ثم تحوله إلى PNG.
- المعالجة اللاحقة المسموحة محصورة في PNG Raster موجود: قص، حشو، إعادة تحجيم، وضغط. كتابة الاسم وبناء الشعار تتمان داخل توليد أو تحرير الصورة Raster مباشرة.
- استخدم فقط الأصول التي يملكها التاجر أو يملك ترخيصًا لها.
- لا تقدّم بحث علامة أو نطاق على أنه تصريح قانوني. إذا طلب المستخدم تسجيلًا أو خلوصًا قانونيًا، أوقف الاعتماد وأحله لمختص.
- لا تضع اسمًا إنجليزيًا، شعارًا فرعيًا، نصًا إضافيًا، mockup، ظلًا، علامة مائية، أو خلفية شطرنجية مزيفة في صورة الرفع.
- لا تقل «خلفية شفافة» من المظهر فقط؛ يجب أن يحتوي PNG على alpha فعلي وبكسلات شفافة.
- لا تكتفِ بلوحة هوية تجمع كل شيء. لوحة الهوية للعرض فقط، وليست بديلًا عن ملفي الشعار والأيقونة المستقلين.
- يمكن للوحة عرض عينات الألوان بصريًا، لكن قيم HEX ونسب التباين المعتمدة يجب أن تظهر كنص قابل للنسخ خارج الصورة.
- تقرير الفحص نص خارج الصور، وليس جزءًا مرسومًا داخل اللوحة.

## عقد التسليم

سلّم للتاجر **أربعة مخرجات منفصلة لا أقل ولا أكثر**:

1. لوحة الهوية الكاملة `brand-board.png` بمقاس 1536×1024، أو برومبتها المستقل في وضع `prompts_only`.
2. ألوان الهوية نصًا، مع HEX والأدوار ونسب التباين.
3. صورة الشعار العربي `logo-ar.png` بمقاس 1024×256، أو برومبتها المستقل.
4. أيقونة المتجر `store-icon.png` بمقاس 32×32 مع تقرير فحص نصي، أو برومبتها المستقل.

أرفق `brand-kit.json` كملف تقني داعم؛ لا تعدّه مخرجًا خامسًا موجهًا للتاجر.

## تعريف النجاح

يستلم التاجر النتائج الأربع منفصلة، ويستطيع رفع صورة الشعار PNG والأيقونة دون تغيير المقاس أو إزالة الخلفية، وينسخ الألوان من نص واضح، ويراجع الحزمة كاملة في لوحة مستقلة. لا توجد قيم ثابتة موروثة من مثال سابق.
