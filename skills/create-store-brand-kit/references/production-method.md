# منهج الإنتاج

## قبل الاختيار

لا تقرأ هذا المرجع لتفرض صيغة أو مقاسًا على معاينات المرحلة الأولى، ولا تشغّل الفاحص عليها. معاينات الخيارات صور مرئية للاختيار فقط بأي صيغة أو مقاس تدعمه المنصة. الترتيب الملزم هو: سطر `الخيار N`، ثم استدعاء صورة واحدة لذلك الخيار، ثم انتظار ظهورها وربط نتيجة الأداة نفسها بـ`optionMap[N]`.

لا ترسل أكثر من بطاقة `<single-image-prompt>` إلى عملية واحدة. التصميم نفسه يُنشأ بصريًا، لا بـPython/Pillow أو SVG. لا يبدأ أي تصدير نهائي قبل `selectedReference = optionMap[N]` بعد اختيار التاجر.

## المرجع المختار

تبقى لوحة الخيار المختار مرجع الهوية الكامل والكتالوج البصري كما ظهرت. لا يلزم تحويلها إلى ملف نهائي أو تسميتها أو تغيير مقاسها، ولا تدخل الفاحص. استخدم المرجع المربوط بالرقم المختار فقط، وليس آخر صورة ظهرت.

## إنشاء الشعار وتصديره

1. أنشئ أصل الشعار بصريًا من جديد باستخدام المرجع المختار كمرجع بصري مباشر، واطلب الاسم العربي فقط وشفافية حقيقية.
2. إذا خرج الأصل RGBA صحيحًا بمقاس مختلف، لاءم الأصل كاملًا مع الحفاظ على النسبة داخل لوحة شفافة 1024x256. لا تقصه ولا تمدده ولا تعِد تصميمه.
3. إذا خرج RGB أو معتمًا، أزل الخلفية فقط بتحرير الصور المدمج أو معالجة raster محلية، مع حفظ التصميم. يجوز اختيار خلفية مسطحة عالية التباين في التوليد الأول لتسهيل إزالتها.
4. صدّر `logo-ar.png` بمقاس 1024x256، PNG RGBA 8-bit غير متداخل، <=1,950,000 بايت.

## إنشاء الأيقونة وتصديرها

1. استخدم صورة `logo-ar.png` النهائية نفسها مرجعًا بصريًا مباشرًا، وأنشئ أصل الأيقونة مرة واحدة من العلامة الفعلية داخلها، بلا نص. لا تستخدم وصفًا نصيًا وحده ولا آخر معاينة.
2. بعد قبول هندسة الأيقونة، ثبّت أصلها. إذا كانت المشكلة شفافية أو مقاسًا فقط، استخدم تحرير/إزالة خلفية مدمجًا أو معالجة raster محلية على الأصل نفسه؛ لا تعِد ابتكار الرمز أو توليد هندسة جديدة.
3. لاءم الأصل كاملًا مع الحفاظ على النسبة داخل لوحة شفافة 32x32، بلا قص أو تشويه، ثم صدّر `store-icon.png`، PNG RGBA 8-bit غير متداخل، <=1,950,000 بايت.

Python/Pillow وأدوات raster مسموحة فقط بعد توليد الأصل بصريًا لإزالة الخلفية أو الملاءمة أو التصغير أو التحسين أو التصدير. لا تستخدمها لتصميم العلامة. لا تطلب من التاجر تشغيل CLI أو منح إذن API، ولا تنتقل إلى تطبيق أو موصل أو مولد صور خارجي.

## تحديد اللونين الرسميين

لا تثبّت اللونين من لوحة التصور أو من خلفية العرض. بعد اكتمال `logo-ar.png`، عاين مساحات العلامة المرئية داخل الشعار النهائي نفسه:

1. اللون الأساسي هو العائلة اللونية الأكثر حضورًا وتمثيلًا للعلامة.
2. اللون الثانوي لون داعم ظاهر بوضوح داخل العلامة.
3. استبعد الشفافية وخلفية المعاينة أو العرض أو المشهد، والظلال واللمعات والانعكاسات، والحياديات المستخدمة للعرض فقط.
4. لا تعتمد الأسود أو الأبيض لمجرد أنهما خلفية؛ يجوز اعتمادهما فقط إذا كانا مقصودين وظاهرين داخل العلامة نفسها.
5. عند وجود خامة أو تدرج، اختر HEX مسطحًا يمثل العائلة اللونية بدل لون لمعان أو ظل عابر.

هذا تحقق بعد اكتمال الشعار، وليس قيدًا يحصر إبداعه في درجتين أو سببًا لإعادة تلوينه.

## الفحص النهائي

افحص الشعار والأيقونة فقط:

```bash
node scripts/validate-brand-kit.mjs <primary-hex> <secondary-hex> <logo-asset> <icon-asset>
```

يلزم الاسمان والمقاسان الدقيقان، PNG RGBA 8-bit غير متداخل، الأركان الأربعة شفافة و1% على الأقل من البكسلات `alpha=0`، وحجم كل أصل <=1.95MB. RGB أو خلفية شطرنجية مرسومة لا تحقق الشفافية. الفاحص البنيوي لا يستطيع إثبات عدم القص أو تطابق هندسة الرمز؛ افحصهما بصريًا داخليًا قبل التسليم.

لا يوجد SVG أو fallback تصميمي. إذا فشل أصل بسبب الشفافية أو المقاس، أصلح تصدير الأصل نفسه وأعد الفحص.

## التسليم

بعد الاختيار فقط، سلّم `logo-ar.png` ثم `store-icon.png` ثم `1. اللون الأساسي: #RRGGBB` ثم `2. اللون الثانوي: #RRGGBB`. لا تعد لوحة المرجع ملفًا ثالثًا ولا تعرض تقرير الفحص.
