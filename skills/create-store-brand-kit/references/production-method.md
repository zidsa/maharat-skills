# منهج الإنتاج

## متحكم الاستدعاءات

البرومبت الشامل يضبط الحالة والتسلسل فقط ولا يُرسل إلى أداة الصور. أنشئ لكل أصل payload قصيرًا مستقلًا: `BOARD_ONLY` للوحة وحدها، ثم `LOGO_ONLY` للشعار وحده، ثم `ICON_ONLY` للأيقونة وحدها. لا يحمل أي payload تعليمات أصل آخر أو الفحص أو التسليم. طلب صورة واحد = أصل واحد = canvas/ملف واحد؛ لا contact sheet ولا mega prompt ولا أصلان في صورة واحدة.

احتفظ بكل payload داخليًا ولا تعرضه للتاجر. بعد الاعتماد نفّذ `LOGO_ONLY`، وانتظر نتيجة الصورة الفعلية وخزنها في `finalLogoReference`، ثم اجتز بوابة الاسم ونفّذ `ICON_ONLY` مع صورة `finalLogoReference` الفعلية مرفقًا مرجعيًا. لا تكتب للتاجر ولا تتوقف بين استدعائي الشعار والأيقونة.

## لوحة المعاينة

أنشئ لوحة هوية واحدة باستدعاء `BOARD_ONLY` مستقل. لا تفرض عليها صيغة أو اسم ملف أو مقاسًا نهائيًا، ولا تشغّل الفاحص عليها. خزّن نتيجة الصورة نفسها في `latestBoardReference`.

بعد ظهور أي نتيجة مرئية لا تعد التوليد تلقائيًا بسبب الإملاء أو الذوق أو الجودة. يسمح بمحاولة إضافية واحدة فقط إذا كان الفشل تقنيًا ولم ينتج أي صورة. عند ملاحظة التاجر، استخدم أحدث لوحة مرئية والملاحظة مرجعين مباشرين لإنشاء لوحة معدلة واحدة.

الاسم الحرفي يظهر مرة واحدة فقط في التكوين الرئيسي المواجه. كل تطبيق آخر في اللوحة يستخدم العلامة وحدها بلا نص. لا تجمع بدائل أو مقارنات داخل الصورة.

## المرجع المعتمد

عند الموافقة الصريحة، ثبّت `approvedBoardReference` إلى أحدث لوحة مرئية وافق عليها التاجر. لا تقص اللوحة ولا تحولها إلى ملف ثالث ولا تعيد إنشاءها. إذا فُقدت الحالة الخفية، استعد أحدث لوحة مرئية من سجل المحادثة.

## إنشاء الشعار وتصديره

1. نفّذ استدعاء `LOGO_ONLY` وحده وأنشئ أصل الشعار بصريًا من الصفر باستخدام `approvedBoardReference` مرجعًا بصريًا مباشرًا، محافظًا على العلامة والأسلوب والألوان.
2. اطلب `merchantNameLiteral` مرة واحدة فقط، بلا موك أب أو خلفية عرض أو نص إضافي، وبشفافية حقيقية.
3. إذا خرج الأصل RGBA صحيحًا بمقاس مختلف، لاءم الأصل كاملًا مع الحفاظ على النسبة داخل لوحة شفافة 1024x256. لا تقصه ولا تمدده ولا تعِد تصميمه.
4. إذا خرج RGB أو معتمًا، أزل الخلفية فقط بتحرير الصور المدمج أو معالجة raster محلية مع حفظ التصميم. يجوز اختيار خلفية مسطحة عالية التباين في التوليد لتسهيل إزالتها.
5. انتظر نتيجة الصورة الفعلية، ثم صدّر `logo-ar.png` بمقاس 1024x256، PNG RGBA 8-bit غير متداخل، وحجم لا يتجاوز 1,950,000 بايت، وخزّن الصورة النهائية نفسها في `finalLogoReference`.

## بوابة الاسم

قارن الاسم الظاهر في صورة الشعار النهائية بـ`merchantNameLiteral` حرفًا حرفًا وبالترتيب، بما في ذلك النقاط والتشكيل والفرق بين `ه` و`ة`. لا تبدأ الأيقونة قبل `finalNameVerified = true`.

إذا فشل التطابق، حرر مساحة النص في أصل الشعار نفسه مع الحفاظ على العلامة والأسلوب والألوان. لا تعِد ابتكار الاتجاه ولا تستخدم Python/Pillow أو SVG لتصميم شعار بديل.

## إنشاء الأيقونة وتصديرها

1. بعد تحقق الاسم مباشرة، نفّذ استدعاء `ICON_ONLY` وحده وارفق صورة `finalLogoReference` الفعلية مرجعًا بصريًا مباشرًا.
2. أنشئ أصل الأيقونة من العلامة الفعلية داخل الشعار، بلا اسم أو حروف. لا تستخدم وصفًا نصيًا وحده ولا تنشئ رمزًا جديدًا.
3. بعد قبول هندسة الأيقونة، ثبّت أصلها. إذا كانت المشكلة شفافية أو مقاسًا فقط، عالج الأصل نفسه ولا تعِد ابتكار الرمز.
4. لاءم العلامة كاملة مع الحفاظ على النسبة داخل لوحة شفافة 32x32، بلا قص أو تشويه، ثم صدّر `store-icon.png`، PNG RGBA 8-bit غير متداخل، وحجم لا يتجاوز 1,950,000 بايت.

Python/Pillow وأدوات raster مسموحة فقط بعد توليد الأصل بصريًا لإزالة الخلفية أو الملاءمة أو التصغير أو التحسين أو التصدير. لا تستخدمها لتصميم العلامة. لا تطلب من التاجر تشغيل CLI أو منح إذن API، ولا تنتقل إلى تطبيق أو موصل أو مولد صور خارجي.

## تحديد اللونين الرسميين

لا تثبّت اللونين من لوحة المعاينة أو خلفية العرض. بعد اكتمال `logo-ar.png`، عاين مساحات العلامة المرئية داخله:

1. اللون الأساسي هو العائلة اللونية الأكثر حضورًا وتمثيلًا للعلامة.
2. اللون الثانوي لون داعم ظاهر بوضوح داخل العلامة.
3. استبعد الشفافية والظلال واللمعات والانعكاسات والحياديات المستخدمة للعرض فقط.
4. لا تعتمد الأسود أو الأبيض لمجرد أنهما خلفية؛ يجوز اعتمادهما فقط إذا كانا مقصودين وظاهرين داخل العلامة نفسها.
5. عند وجود خامة أو تدرج، اختر HEX مسطحًا يمثل العائلة اللونية بدل لمعان أو ظل عابر.

هذا تحقق بعد اكتمال الشعار، وليس قيدًا يحصر إبداعه في درجتين أو سببًا لإعادة تلوينه.

## رفض استدعاء تالٍ

لا تختر استكمالًا متعدد الردود مسبقًا ولا تتوقف اختياريًا بعد الشعار. حاول تنفيذ الاستدعاءين النهائيين بالتتابع الصامت. فقط إذا رفضت المنصة أو الأداة فعليًا استدعاء الصورة التالي، احتفظ بـ`approvedBoardReference` و`finalLogoReference` و`finalNameVerified` وسجّل العملية التالية. استأنفها عند متابعة التاجر من دون إعادة المعاينة أو فقد الملف الناجح. هذا تعافٍ من رفض فعلي، وليس فرع تشغيل عاديًا.

## الفحص النهائي

افحص الشعار والأيقونة فقط بهذا النمط، مع استبدال القيم والمسارات الفعلية:

```bash
node scripts/validate-brand-kit.mjs "#5A2134" "#8C4517" ./logo-ar.png ./store-icon.png
```

يلزم الاسمان والمقاسان الدقيقان، PNG RGBA 8-bit غير متداخل، الأركان الأربعة شفافة و1% على الأقل من البكسلات `alpha=0`، وحجم كل أصل لا يتجاوز 1.95MB. RGB أو خلفية شطرنجية مرسومة لا تحقق الشفافية. الفاحص البنيوي لا يستطيع إثبات عدم القص أو تطابق هندسة الرمز أو صحة الاسم؛ افحصها بصريًا داخليًا قبل التسليم.

لا يوجد SVG أو fallback تصميمي. إذا فشل أصل بسبب الشفافية أو المقاس، أصلح تصدير الأصل نفسه وأعد الفحص.

## التسليم

بعد اكتمال الأصلين فقط، سلّم `logo-ar.png` ثم `store-icon.png` ثم `1. اللون الأساسي: #RRGGBB` ثم `2. اللون الثانوي: #RRGGBB`. لوحة المعاينة ليست ملف تسليم ثالثًا ولا يعرض تقرير الفحص.
