# عقد المدخلات

## مطلوب فقط

- اسم المتجر بالعربية كما يجب أن يظهر في الشعار.
- ما الذي يبيعه المتجر، بكلمات بسيطة.

لا تطلب الجمهور أو المناسبة أو تفضيلًا لونيًا أو أسلوبيًا أو قائمة أصول كي تبدأ. إن ذكر التاجر تفضيلًا من تلقاء نفسه، احترمه من دون تحويله إلى حقل ثالث.

## الاسم الحرفي

- خزّن الاسم المرسل في `merchantNameLiteral` من دون تغيير أي محرف أو تشكيل أو مسافة داخلية.
- يجوز استخدام `trim` لاختبار أن القيمة ليست فارغة فقط؛ لا تحفظ ناتج التقليم بدل القيمة الأصلية.
- لا تصحح الاسم ولا تطبّعه ولا تبدل `ه` و`ة`. الاسم «نظره» يبقى «نظره» ولا يتحول إلى «نظرة».

## حالة اللوحة والموافقة

- خزّن كل لوحة ظاهرة ناجحة فورًا في `latestBoardReference`.
- افحص الموافقة الصريحة قبل أي fallback يعيد المعاينة. عند «اعتمدها» أو «موافق»، اربط `approvedBoardReference` بأحدث لوحة مرئية وافق عليها التاجر.
- إذا فُقدت الحالة الخفية، استعد أحدث لوحة مرئية من سجل المحادثة بدل إعادة توليدها.
- لا تعتبر الإعجاب العام موافقة. بعد المعاينة أو التعديل اسأل: `هل تعتمد هذه الهوية، أو تبي تعديلًا محددًا؟`
- عند ملاحظة أو رفض، أنشئ لوحة معدلة واحدة من أحدث لوحة والملاحظة. لا تعرض بدائل متعددة.

## متى تتوقف

- إذا غاب الاسم العربي أو ما الذي يبيعه المتجر.
- إذا طلب التاجر نسخ علامة أخرى أو انتحالها.
- بعد ظهور لوحة المعاينة: اسأل سؤال الاعتماد الواحد وتوقف.
- إذا فشل إنشاء المعاينة تقنيًا بلا أي صورة، أعد العملية مرة واحدة فقط. لا تعِدها تلقائيًا بعد ظهور صورة مرئية.
- إذا بقي الاسم المرسوم غير مطابق بعد أول شعار ومحاولتي تصحيح، توقف قبل الأيقونة والألوان والتسليم النهائي، وصرّح بتعذر تثبيت الاسم. لا تبدأ محاولة ثالثة.
- إذا تعذر إخراج الشعار أو الأيقونة بالمواصفات النهائية بعد معالجة الأصل المولد، لا تدّع النجاح ولا تطلب API أو CLI أو خدمة خارجية.
