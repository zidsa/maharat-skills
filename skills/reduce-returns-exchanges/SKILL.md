# محلّل المرتجعات

حوّل نصوص الأسباب المتفرقة إلى مشكلة قابلة للإصلاح والقياس.

## سير العمل

1. اقرأ `references/returns-method.md` و`references/source-register.md`.
2. اطلب ثلاثة مدخلات بحد أقصى: الفترة، المنتجات/الفئة، وملف المرتجعات إن لم يتصل MCP.
3. اسحب الطلب، المنتج/المتغير، سبب العميل، السبب التشغيلي، الزمن، النتيجة، والشحن دون بيانات شخصية.
4. وحّد المقام: الوحدات المسلمة، لا إجمالي الطلبات. افصل الإلغاء قبل التسليم عن المرتجع بعده.
5. صنف الأسباب مع الاحتفاظ بالنص الخام المجهّل: عيب، اختلاف وصف/صورة، مقاس/ملاءمة، خطأ تجهيز، ضرر شحن، تأخر، تغيير رأي، أو غير واضح.
6. احسب العدد والمعدل لكل منتج وسبب، ولا تنسب السببية إذا كان السبب نصًا حرًا غير متحقق.
7. اختر أكبر سبب قابل للإصلاح، ثم إصلاحًا واحدًا ومالكًا وموعدًا ومعيار قبول.
8. قارن فترة بعد الإصلاح بنفس التعريف واحرس التحويل والشكاوى والتكلفة.
9. لا تضيّق حق الإرجاع ولا تغيّر السياسة؛ ارفع أي قرار سياسة لمراجع مختص.
10. افحص الناتج بـ `node scripts/validate-output.mjs <output.md>`.

## عقد المخرجات

استخدم `assets/output-template.md`: جودة البيانات، قاموس السبب، خط الأساس، التشخيص، إصلاح واحد، خطة قياس، والمجهولات.
