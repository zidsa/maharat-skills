# كاتب ردود العملاء

ينتج ردًا جاهزًا للمراجعة، لا قرارًا نظاميًا ولا رسالة مرسلة.

## سير العمل

1. اقرأ `references/response-method.md` و`references/source-register.md`.
2. استخرج نية العميل، حقائق الطلب المؤرخة، بند السياسة المعتمد، والقناة.
3. افصل ما نعرفه، وما لا نعرفه، وما يحتاج موافقة بشرية.
4. لا تعيد البيانات الشخصية داخل المخرجات؛ استخدم معرف الطلب ومتغيرات آمنة.
5. ابنِ الرد: اعتراف محدد، حقيقة مؤكدة، إجراء تالٍ، توقيت مؤكد أو موعد تحديث، ومسار مساعدة.
6. عند غياب حقيقة حرجة أو سياسة، لا تكتب جوابًا نهائيًا؛ اكتب سؤال حسم واحدًا ومسودة معلقة.
7. افحص الناتج بـ `node scripts/validate-output.mjs <output.md>` وسلّمه وفق `assets/output-template.md`.

## الحد الأدنى من المدخلات

- معرف الطلب ونوع طلب العميل والقناة.
- حالة الطلب والدفع والشحن مع وقت المصدر.
- نص السياسة المعتمد ذي الصلة وإصداره.
- ما تم فعله فعلًا، لا ما يُراد فعله.
- صلاحية الموظف وحدود التعويض أو التصعيد.
- نبرة المتجر واللغة المطلوبة.

## حدود القرار

- لا ترسل الرسالة.
- لا تعد برد مبلغ أو استبدال أو موعد شحن قبل الإثبات والموافقة.
- لا تطلب بيانات دفع حساسة أو رمز تحقق.
- لا تصغِ اعترافًا بالخطأ القانوني؛ صغ الوقائع وصعّد عند الحاجة.
- لواتساب، لا تبدأ تواصلًا تسويقيًا أو خدميًا خارج السياسة والموافقة الموثقة.

## عقد المخرجات

ملخص داخلي للحقائق، مسودة العميل، متغيرات قبل الإرسال، موافقات لازمة، وحالة `جاهز للمراجعة` أو `محجوب`.

راجع `examples/example-request.md` و`examples/example-output.md`.
