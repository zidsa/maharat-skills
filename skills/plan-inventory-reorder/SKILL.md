# مخطّط طلب المخزون

المهارة تصنع قرار شراء قابلًا للمراجعة؛ لا تنشئ طلب شراء ولا تعدل مخزون زد.

## سير العمل

1. اقرأ `references/reorder-method.md` و`references/source-register.md`.
2. وحّد وحدة القياس والموقع والـSKU والفترة، وافصل المرتجعات والإلغاءات عن الطلب المستهلك.
3. احسب الطلب اليومي من نافذة معلنة، ولا تستخدم نافذة قصيرة كموسمية ثابتة.
4. احسب موضع المخزون ونقطة إعادة الطلب بالمعادلات في المرجع.
5. أدخل مخزون الأمان كسياسة معتمدة أو سيناريو معلن؛ لا تخترع مستوى خدمة.
6. طبّق مهلة المورد وMOQ وحجم العبوة وموعد الطلبات القادمة.
7. أعط قرارًا لكل SKU: اطلب الآن، راقب حتى تاريخ، أو محجوب بسبب بيانات.
8. افحص الناتج بـ `node scripts/validate-output.mjs <output.md> <inventory.json>`.

## الحد الأدنى من المدخلات

- SKU والموقع ووحدة القياس.
- مبيعات أو استهلاك يومي مؤرخ، مع المرتجعات والإلغاءات.
- المتاح والمحجوز والطلبات المؤكدة القادمة وموعدها.
- مهلة المورد بالنطاق ومصدرها وتاريخ تحديثها.
- مخزون الأمان أو قاعدة اعتماده.
- MOQ وحجم العبوة والحد الأقصى أو قيود النقد والتخزين.

## حدود القرار

- إذا غابت المهلة أو الطلب أو رصيد الموقع، احجب الكمية النهائية.
- لا تجمع مواقع لا يمكن تحويل المخزون بينها.
- لا تعامل الطلب القادم المتأخر عن الحاجة كمتاح.
- لا تستخدم EOQ دون تكلفة طلب وتكلفة احتفاظ موثقتين.
- اعرض سيناريو أساس وضغط عندما تكون البيانات متذبذبة.

## عقد المخرجات

سجل مدخلات، معادلات ظاهرة، قرار لكل SKU، سيناريو ضغط، قيود الشراء، وفجوات تمنع الطلب.

استخدم `assets/output-template.md` وراجع أمثلة `examples/`.
