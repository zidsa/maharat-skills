# مختبر الأسعار

لا يغيّر السعر لأن المنافس أرخص أو لأن المبيعات هادئة. هذه المهارة تبيّن هل توجد أرقام كافية لقرار، وتحول أي اقتراح إلى تجربة محدودة قابلة للتراجع.

## قبل أن تبدأ

1. اقرأ `references/method.md` و`references/source-register.md`.
2. اقرأ من المتجر أو ملف التاجر السعر الحالي، التكلفة المتغيرة، رسوم الدفع أو المنصة، دعم الشحن أو الخصم، وسجل الطلبات أو المخزون للفترة المحددة.
3. إذا كانت التكلفة أو الرسوم غير متاحة، لا تعرض سعرًا مقترحًا رقميًا. اشرح ما ينقص وقدم فقط قائمة قرار.

## سير العمل

1. ثبّت وحدة القياس: منتج/متغير محدد، السوق والعملة، وهل الضريبة والشحن داخل السعر أو خارجه.
2. اكتب معادلة الهامش من مدخلات واضحة، وميّز ما هو ثابت عما يتغير حسب الطلب أو القناة.
3. افصل مشكلة السعر عن العرض والصفحة والمخزون. لا تصف هبوط الطلب بأنه «السعر» بلا دليل.
4. عند توافر الأرقام، قارن 3 سيناريوهات فقط: الحالي، تعديل صغير، وعرض محدود أو حزمة، مع بيان الافتراضات لا الوعود.
5. صمم تجربة صغيرة: منتج أو شريحة أو مدة، مع شروط إيقاف تحمي الهامش والمخزون والمرتجعات.
6. اعرض المعاينة واطلب موافقة. لا تعدّل السعر ولا تنشر عرضًا.
7. افحص النتيجة بـ `node scripts/validate-output.mjs <output.md>`.

## المدخلات الدنيا

- المنتج أو المتغير والسعر الحالي.
- التكلفة المتغيرة والرسوم المرتبطة بالطلب، أو تصريح واضح بأنها غير متاحة.
- هدف القرار: هامش، تحويل، تصريف مخزون، أو تموضع.

## قواعد لا تتغير

- لا توصي بسعر رقمي إذا لم نعرف التكلفة أو الرسوم الأساسية.
- لا تقول إن العميل «حساس للسعر» أو إن التخفيض «سيزيد المبيعات» بلا تجربة أو دليل.
- لا تستخدم سعر منافس غير موثق أو من سوق مختلف كحكم نهائي.
- لا تجعل السعر دون التكلفة أو تعِد بربح؛ اعرض حارسًا وتوقفًا واضحين.
- لا تعدل أسعار المتجر أو العروض دون موافقة صريحة.

## عقد المخرجات

استخدم `assets/output-template.md`. يجب أن يفرق التاجر بين رقم محسوب، افتراض تجربة، وقرار يحتاج بيانات قبل الاستمرار.
