# حساب العرض والاختبار

المقيّم `scripts/calculate-offer.mjs` يطبق هذه المعادلات نفسها. إذا اختلف رقم كتبته عن رقمه بأكثر من 0.01 فرقمه هو الصحيح.

## 1. أساس الضريبة أولًا

اسأل سؤالين قبل أي حساب: هل المتجر مسجل في ضريبة القيمة المضافة؟ وهل الأسعار المعروضة شاملة الضريبة؟

| الحالة | `stated_basis` | الإيراد الصافي من المبلغ الذي يدفعه العميل |
|---|---|---|
| مسجل، والأسعار شاملة الضريبة (الغالب في السعودية) | `net_of_vat` | المبلغ ÷ 1.15 |
| مسجل، والأسعار المعروضة لا تشمل الضريبة | `vat_exclusive_prices` | المبلغ نفسه، والضريبة تضاف فوقه وتُورَّد |
| غير مسجل | `not_registered` | المبلغ نفسه، ولا تُستبعد ضريبة |

- الضريبة التي يحصّلها المتجر المسجل ليست إيرادًا له؛ تُورَّد للهيئة. حسابها إيرادًا يضخم الهامش بنحو 31% في المثال أدناه.
- أدخل التكاليف بلا ضريبة إذا كان المتجر مسجلًا ويسترد ضريبة مشترياته. غير المسجل يدخلها كما دفعها.
- الشحن الذي يدفعه العميل يدخل في المبلغ نفسه ويُعامل بالأساس نفسه.

## 2. هامش المساهمة لكل طلب

```
قيمة البضاعة المعروضة = سعر القطعة × عدد القطع   (أو سعر الباقة)
ما يدفعه العميل       = قيمة البضاعة − الخصم + الشحن الذي يدفعه العميل
الإيراد الصافي         = ما يدفعه العميل ÷ 1.15   (net_of_vat فقط)
رسوم الدفع            = ما يدفعه العميل × النسبة ÷ 100 + المبلغ الثابت
التكاليف المتغيرة      = عدد القطع × تكلفة القطعة + تكلفة شركة الشحن + التغليف + رسوم الدفع + تكلفة متغيرة أخرى
هامش المساهمة         = الإيراد الصافي − التكاليف المتغيرة
```

- التكاليف المطلوبة: `unit_cost` و`shipping_cost` و`packaging_cost` و`payment_fee_pct` و`payment_fee_fixed`. الصفر يُكتب صفرًا صريحًا؛ الخانة الفارغة أو الغائبة توقف الحساب بحالة `blocked_missing_costs`.
- الهامش هنا قبل الإعلانات والمرتجعات والتكاليف الثابتة. اذكر ما استُبعد.
- رسوم الدفع تختلف بين مدى والبطاقات والتقسيط (تابي وتمارا). استخدم متوسط كشف بوابة الدفع الفعلي، لا نسبة عامة.

## 3. العروض المرشحة

| النوع | `type` | ما يتغير | إعداده في زد (مسودة فقط) |
|---|---|---|---|
| خصم بالنسبة | `percent_discount` | الخصم = قيمة البضاعة × النسبة | Coupons: `discount_type: "p"` |
| خصم ثابت | `fixed_discount` | الخصم = المبلغ | Coupons: `discount_type: "f"` |
| شحن مجاني فوق حد | `free_shipping` | الشحن الذي يدفعه العميل = 0، والسلة تكبر إلى الحد | Coupons: `free_shipping: true` و`total`، أو إعداد الشحن في لوحة زد |
| باقة | `bundle` | قيمة البضاعة = سعر الباقة، والتكلفة = عدد القطع × تكلفة القطعة | BundleOffers: `start_date` و`end_date` |
| تغيير سعر | `price_change` | سعر القطعة الجديد | Products (تعديل السعر) |

- `min_goods_value` حد السلة المعروض. المقيّم يرفض عرضًا سلته المفترضة أقل من حده؛ ارفع `units_per_order`.
- **السلة الأكبر تُحسب بتكلفتها كاملة**: في الشحن المجاني فوق حد والباقة، كل قطعة إضافية لها تكلفتها. لا تُبقِ تكلفة البضاعة ثابتة وقيمة السلة ترتفع.
- الخصم ممنوع جمعه مع كوبون آخر ما لم يُحسب الجمع صراحة. في زد يمكن حصر الكوبون بالمنتجات غير المخفضة (`apply_to: "non_discounted_products"`).

## 4. الزيادة المطلوبة للتعادل

```
الزيادة المطلوبة % = (هامش الطلب الحالي ÷ هامش الطلب مع العرض − 1) × 100
```

- مثال: هامش 65.48 ثم 53.76 مع الخصم ← تحتاج 21.81% طلبات أكثر ليبقى مجموع الهامش كما هو.
- إذا كان هامش العرض صفرًا أو أقل فلا تعادل ممكن (`null`)، ولا يُختبر العرض.
- قيمة سالبة تعني أن الطلب المؤهل يربح أكثر من الطلب الحالي، وهذا لا يكفي للحكم. في السلة الأكبر احسب أيضًا:

```
هامش السلة نفسها بلا عرض   = نفس القطع بالسعر الكامل وبشحن يدفعه العميل
تكلفة العرض على السلة نفسها = هامش السلة بلا عرض − هامش السلة مع العرض
مكسب الترقية              = هامش السلة مع العرض − هامش الطلب الحالي
نسبة الترقية المطلوبة %     = تكلفة العرض ÷ (تكلفة العرض + مكسب الترقية) × 100
```

نسبة الترقية هي أقل حصة من الطلبات المؤهلة يجب أن تأتي من عملاء رفعوا سلتهم بسبب العرض. البقية كانوا سيشترون السلة نفسها ويأخذون الشحن مجانًا.

## 5. تصميم الاختبار

- اختبار واحد لعرض واحد، ومتغير واحد يتغير. لا تجمع خصمًا وشحنًا مجانيًا في اختبار واحد.
- مدة من 7 إلى 28 يومًا، تبدأ بعد تاريخ التحليل وبعد الموافقة، ولها تاريخ نهاية مكتوب في إعداد زد.
- تجنب فترة تشوّه المقارنة إن لم تكن مقصودة: أيام الراتب، ورمضان، واليوم الوطني، والجمعة البيضاء.
- **شرط التوقف**: رقم يمكن قراءته أسبوعيًا من لوحة زد، مثل هامش المساهمة الأسبوعي أو تكلفة الشحن الفعلية أو تأخر التجهيز.
- **مقياس النجاح**: مجموع هامش المساهمة في المدة مقارنة بخط الأساس للمدة نفسها، لا عدد الطلبات وحده.
- **بلا سجل طلبات**: قل ذلك صراحة، ولا تكتب نسبة تحويل أو زيادة متوقعة. اجعل هدف الاختبار جمع أول خط أساس، وشرط التوقف حدًا للخسارة. المقيّم يرفض أي حقل `expected_*` أو `predicted_*` أو `forecast_*` حين `history.available` تساوي `false`.
- **ترخيص التخفيضات**: إذا تضمن الملف أي خصم (بالنسبة أو ثابت أو باقة أرخص من القطع منفردة أو خفض سعر) فأضف فحص `moc_discount_licence`. صيغته: «تحقق من اشتراط الترخيص» من وزارة التجارة قبل الإعلان. لا تجزم بحكم نظامي لعرض بعينه.
- إعداد زد يبقى `draft_awaiting_approval`. المهارة لا تستدعي أداة إنشاء أو تعديل في Coupons أو BundleOffers أو Products.

## 6. مخطط ملف العرض

```json
{
  "analysis_date": "2026-09-28",
  "vat": { "registered": true, "prices_include_vat": true },
  "stated_basis": "net_of_vat",
  "baseline": {
    "unit_price": 69, "units_per_order": 2, "shipping_charged": 25,
    "costs": { "unit_cost": 24, "shipping_cost": 21, "packaging_cost": 3, "payment_fee_pct": 2, "payment_fee_fixed": 1 },
    "stated_margin": 65.48
  },
  "margin_floor": 55,
  "history": { "available": true, "source": "zid_orders" },
  "offers": [
    { "id": "pct10", "type": "percent_discount", "value": 10, "stated_margin": 53.76, "stated_break_even_uplift_pct": 21.81 }
  ],
  "test": {
    "offer_id": "pct10", "start_date": "2026-10-04", "end_date": "2026-10-17",
    "success_metric": "…", "stop_condition": "…",
    "zid_setup": { "tool": "Coupons", "status": "draft_awaiting_approval", "fields": {} }
  },
  "pre_launch_checks": [ { "id": "moc_discount_licence", "status": "to_verify", "note": "…" } ],
  "approvals_needed": ["…"]
}
```

- `stated_margin` مطلوب للأساس ولكل عرض، و`stated_break_even_uplift_pct` مطلوب لكل عرض (`null` فقط إذا لا تعادل ممكن).
- `stated_same_basket_margin` و`stated_upgrade_share_pct` يُفحصان إذا كُتبا.
- حالات `moc_discount_licence`: `to_verify` أو `confirmed_obtained` أو `confirmed_not_required`.
- `zid_setup.tool`: ‏Coupons للخصم والشحن المجاني (أو ShippingSettings للشحن)، وBundleOffers للباقة، وProducts لتغيير السعر.
- رموز الخروج: 0 صالح، 1 غير صالح أو ناقص التكاليف، 2 ليس JSON. القيم النائبة مثل «…» تُرفض.

## 7. مثال محلول: أثر الضريبة

حقيبة سفر بسعر معروض 249 ريالًا، تكلفتها 105، ورسوم دفع 6 ريالات للطلب، والمتجر مسجل والأسعار شاملة الضريبة.

| | بلا استبعاد الضريبة (خطأ) | بعد استبعاد الضريبة (صحيح) |
|---|---:|---:|
| الإيراد | 249.00 | 249 ÷ 1.15 = 216.52 |
| هامش المساهمة | 249 − 105 − 6 = 138.00 | 216.52 − 105 − 6 = **105.52** |
| مع خصم 10% (224.10 معروض) | 113.10 | 194.87 − 111 = **83.87** |
| الزيادة المطلوبة للتعادل | 22.02% | **25.82%** |

الحساب الخاطئ يضخم الهامش 31% ويُظهر الخصم أرخص مما هو. لو كان المتجر غير مسجل فالعمود الأول هو الصحيح.
