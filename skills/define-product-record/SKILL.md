# منظّم بيانات المنتج

أنشئ سجلًا واحدًا يمكن للمتجر والصفحة والبحث والمخزون الاعتماد عليه. لا تخلط المنتج الأب بالمتغير، ولا تحول الكمية صفرًا إلى «متاح»، ولا تكتب فائدة أو مكوّنًا بلا مصدر.

## سير العمل

1. اقرأ `references/product-record-method.md` و`references/source-register.md`.
2. ثبّت السوق والعملة والمنتج الأب والمصادر المصرح بها.
3. افصل خصائص المنتج الثابتة عن خيارات الشراء. اللون أو المقاس خيار عندما يغيّر الاختيار متغيرًا؛ لا تجعله وصفًا حرًا ومتغيرًا في الوقت نفسه.
4. أنشئ معرفًا ثابتًا للمنتج ومعرفًا وSKU فريدين لكل متغير. لا تستخدم ترتيب القائمة كهوية.
5. أنشئ `source_manifest` يحصي كل سجل متغير وارد قبل التنظيف، ثم طابق كل تركيبة خيارات مع متغير واحد فقط. لا تحذف سجلًا متعارضًا؛ انقله إلى `conflicts` واربطه بمانع.
6. سجل السعر والعملة وحالة التوفر والكمية المتتبعة دون تخمين. السعر المقارن لا يجوز أن يكون أقل من أو مساويًا للسعر الحالي.
7. اربط الصور بالمنتج أو المتغير، واحفظ النص البديل والمصدر والترتيب. لا تغيّر شكل المنتج أو كتاباته.
8. امنح كل حقيقة `fact_key` ثابتًا مثل `material.composition`، ثم اربط كل ادعاء أو مكوّن أو تحذير بمصدر خاص بالمنتج والسوق. لا تنشئ معرّفين لحقيقة واحدة، واربط سياسات الشحن والاسترجاع بمراجعها.
9. أنشئ JSON وفق `references/product-record-method.md` وشغّل:

```bash
node scripts/validate-product-record.mjs <product-record.json>
```

10. سلّم ملخص الجاهزية بقالب `assets/output-template.md`. إذا كان المطلوب استيرادًا أو مزامنة بعد ذلك، سلّم الملف إلى `merchant-cat-13` ولا تنفذها هنا.

## المدخلات الدنيا

- السوق والعملة.
- اسم المنتج الأب والفئة والعلامة إن وجدت.
- الخيارات وقيمها والمتغيرات الفعلية.
- SKU لكل متغير، والسعر والتوفر والكمية أو تصريح أنها غير متتبعة.
- الصور الأصلية وملكيتها وارتباطها بالمتغيرات.
- ادعاءات المنتج ومكوناته وتحذيراته ومصادرها.
- سياسة الشحن وسياسة الاسترجاع المنطبقتان.

## قواعد القرار

- المنتج الأب يجمع المعلومات المشتركة؛ المتغير يحمل تركيبة الخيارات وSKU والسعر والمخزون والصورة الخاصة به.
- SKU فريد وغير فارغ لكل متغير.
- المتغير المتتبع بكمية صفر حالته `out_of_stock`، وليس `in_stock` أو غير محدود.
- المتغير غير المتتبع يستخدم `not_tracked` ولا يحمل كمية مختلقة.
- كل تركيبة خيارات كاملة وفريدة.
- كل سجل في `source_manifest` إما ممثل بمتغير واحد أو مذكور صراحةً في تعارض؛ الحذف الصامت ممنوع.
- لا تستخدم تقييمًا أو مراجعة أو مبيعات كحقل إلا من مصدرها الحقيقي؛ هذه المهارة لا تولد تقييمات.
- `ready_for_storefront` ممنوعة عند غياب صورة أو سياسة أو ادعاء أساسي أو عند أي تعارض سعر/مخزون/هوية.
- إتاحة المنتج في Google أو نتيجة غنية ليست مضمونة؛ العقد يجهز البيانات ولا يعد بالظهور.

## عقد المخرجات

1. سجل المصادر.
2. سجل المنتج الأب والادعاءات الموثقة.
3. الخيارات وقيمها.
4. قائمة المتغيرات وSKU والأسعار والمخزون والصور.
5. السياسات المرتبطة.
6. بيان المصدر الكامل، والتعارضات الرسمية، والموانع والحقول الناقصة على مستوى كل عنصر.
7. الحالة: `draft` أو `ready_for_storefront`.

## تعريف النجاح

يمكن تحويل الملف إلى سجل متجر دون تخمين هوية أو سعر أو مخزون، وكل متغير قابل للمطابقة، وكل ادعاء وصورة وسياسة قابلة للتتبع إلى مصدر.
